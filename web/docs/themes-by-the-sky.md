# Orrery — themes by the sky: a brief for the Sonnet session (2026-10-18)

> Owner's ask: is there a light mode; can themes follow the time of day; look at Hyle for the other themes we can
> have. This is the handoff for a Claude Code session on Sonnet in `mbaliga/Orrery` (`web/`).

## Where it stands
- **There is no light mode.** The page has one theme: the AMOLED field (`--field:#000`), the ink
  `236,232,228` at four alphas, Hyle's violet `#8e7bff` and cyan `#35e0ff`, radium `#c7ef9e` for what is yours.
  Settings → Display → Background lets you tint the field but clamps it dark ("a light theme is a separate design").
- **Hyle has one material, not a theme set.** Its contract (Oct 2026): AMOLED black, violet + cyan, an upper-left key
  light, provenance glows (radium on-device, alien for cloud), no hue-only state. Nothing in the Hyle tree names a
  light or a second theme, so "the other themes" are ours to define *inside* Hyle's rules, not to import.
- **The ceiling already knows the sky** (`T.ceiling()` in `src/look.js`): sun altitude (by clock, or by the real sky
  with a place set), moon phase and whether it is up, cloud from the weather. A theme schedule hangs off it.
- The ink is hard-coded in canvases: `236,232,228` appears in `year.js` (8), `plan.js` (6), `dial.js`, `rhythm.js`,
  `space.js` (`INK`), `pulse.js`, `body.js`. CSS already uses tokens.

## The themes (proposed, three, all Hyle)
| Theme | Field | Ink | When, by the sky | Notes |
|---|---|---|---|---|
| **Night** (current) | `#000` | `236,232,228` | sun down, moon or stars | unchanged |
| **Dusk** | `#0b0a12` (a violet-black) | `236,232,228` | within ~70 min of sunrise or sunset, or overcast by day | the light warm and low; the beams at their longest |
| **Day** | `#ece9e2` (paper, slightly warm) | `26,26,30` | sun up | violet and cyan darkened to `#5b4fd6` / `#0f7f93` to hold 4.5:1; radium becomes `#4f7a1f`; the beams become shadow — the same shafts drawn in `multiply` as dapple on paper, not light on black; the stars are not drawn; glass panes go `rgba(255,255,255,.6)` |

Schedule: Settings → Display → **Theme**: Night / Dusk / Day / **By the sky** (default stays Night until the owner says
otherwise). **"By the sky" is continuous, never a step** (owner, 08:27): the theme is a *blend* of the three token sets
driven by the sun's altitude from `T.ceiling()` — Night below −12° (astronomical dusk), Dusk at 0°, Day above +12°,
with smoothstep interpolation of every token (field, ink, violet, cyan, radium, glass, hair) in OKLab so the mid-points
stay clean. The real twilight takes about an hour at this latitude, so the change is imperceptible minute to minute;
re-evaluated each minute (each 10 s near the horizon), written as numeric CSS custom properties and read by the
canvases through `T.theme()`. A manual choice holds until changed. Overcast by day pulls the blend toward Dusk by the
cloud fraction. The light (`drawBeamImage`) takes the same blend: from shafts on black through long warm shafts at
dusk to dapple-shadow on paper. Reduced-motion changes nothing here — this is slower than any motion.

## The colour picker (also for the Code session)
Hyle already has the picker: `src/components/color-picker/hy-color-picker.ts` mounts `public/kit/color-picker.html`
(generated by `scripts/build-color-picker.js` from the tactile kit, verbatim): a hue ring + HSV/RGB/Lab/HCL slice, a
THREE.js model of the space, a palette-and-region builder with a colour-blind-safe option. Orrery should **reuse it,
not rebuild it** (D-AJ): vendor the generated document, mount it lazily in an iframe (`srcdoc`) when the Background row's
`+` is pressed, bridge `hy-color` out. The 670 KB (THREE.js) is loaded only then. The toggle the owner asked for:
**2D** (ring + slice, the traditional picker) ↔ **3D** (the model: pick a colour or a whole palette as a region in the
space) — the kit's cylinder button already switches the view; expose it as a two-stop control. The selection
experience is Arc's: one handle you drag, the page re-themes live under it, a second handle for intensity; release to
keep, Esc to let go; the swatches row remembers the last six. If the picker's size is a problem for the single-file
build, the fallback is the kit's 2D ring + slice reimplemented in canvas (small) and the 3D view left to the iframe.

## The toggle — a question for the owner
The owner asked for "the slanted toggle switch style from Hyle". The tactile kit has seven switches (standard
slot-and-knob, flip, gain O/I/II with a slanted pin, smooth, big knob, square) and none is named slanted. The page now
uses the **standard** slot-and-knob with a cell for the knob; if the one meant is the **gain** (the slanted pin) or
the **flip**, it is a one-row change in `src/style.css` / `settings.js`.

## Build order (one session)
1. **Tokenise the canvases.** One `T.theme()` → `{ field, fieldRgb, ink, violet, cyan, radium, glass }`; replace every
   literal `236,232,228` / `INK` / `FA()` field alpha / hard-coded violet in the canvases with it; call
   `T.canopyRedraw`, `T.canopyStars`, the Year's `kick`, the Dial's `kick` on theme change (`T.on('theme')`).
2. **CSS tokens for the three themes** as `[data-theme]` on `<html>` — field, panel, raised/lift, ink ×4, violet ×3,
   native, cloud, glass, hair; keep `--breath` and `--tx` as they are.
3. **The schedule** in `look.js` beside the ceiling; the Settings row; the About copy (plain, behind the info mark).
4. **The light in Day**: `drawBeamImage` takes the theme — on paper the layers composite with `multiply` and the colour
   is a warm grey; the motes stay radium/cyan but darker. Overcast by day → Dusk, not Day.
5. **Contrast pass** on Day with real text: ≥4.5:1 ink on field and panes, ≥3:1 for marks (Hyle's rule). The brand
   marks (`ASOC.brands`) already carry an `on` colour lifted for dark fields; add `onLight` or use the brand hex.
6. Tests: `tests/steps.js` shots at `g9`, `desk`, `phone` for each theme; a `themetest.js` that forces the ceiling to
   noon / dusk / midnight and asserts `data-theme`.
